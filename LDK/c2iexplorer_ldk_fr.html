Comment traduire c2iExplorer

L'architecture de localisation de c2iExplorer a été conçue pour être simple à utiliser pour les traducteurs. Vous avez un fichier texte de style INI à traduire. Utilisez votre éditeur de texte préféré pour traduire le texte se trouvant entre les guillemets ("") sauf dans la section @Info. Ensuite, éditez la section @Info comme suit :

Translator
votre prénom et nom
TranslatorEmail
votre adresse de courrier électronique
QAContact
prénom et nom de la personne chargée à l'assurance qualité de votre traduction
QAEmail
adresse de courrier électronique du chargé à l'assurance qualité
ProgramName
nom du programme. Doit rester c2iExplorer
ProgramVer
version du programme auquel le fichier de traduction a été fait pour
XlationVer
version de la traduction. Le dernier groupe de chiffres devrait être le même que celui de ProgramVer
LastModified
date de dernière modification du fichier dans le format AAAA/MM/JJ.

Ensuite, traduisez les modèles de rapport de projet situés dans le dossier HTML. Faites une copie des fichiers, puis traduisez-les. N'oubliez pas de les renommer en indiquant la langue entre crochets au tout début du nom de fichier. Ne traduisez pas ce qui est entre < et > (balise HTML), ni entre [ et ] (utilisé à l'interne par c2iExplorer) ni entre <!-- et --> (habituellement un commentaire HTML, mais utilisé de manière spéciale par c2iExplorer).

Finalement, envoyez votre traduction à rener@users.sourceforge.net .

Comment supporter la localisation dans ses modifications de c2iExplorer

Si votre modification comporte des chaînes de caractères à afficher à l'utilisateur, il faudra les placer dans les fichiers de traduction. Vous placez la chaîne dans la section correspondant au nom du module. Le nom de la clé précédent la chaîne est la hiérarchie d'objet ou du code. Si la chaîne était une constante s'il n'y avait pas ce système, le préfixe de variable est mlg. Si votre code utilise une chaîne pour en produire une autre, utilisez le préfixe str. Après le signe égal, entrez votre chaîne à traduire entre guillemets anglais doubles (""). Aucun espace ne sépare la clé du signe égal et le signe égal de la valeur chaîne. Dans votre code, appelez ensuite la fonction LireChaineLocalisee en lui passant le nom du module, la clé à lire et la valeur par défaut s'il y a erreur.

Important : respectez les spécifications du format dans le fichier de localisation. Aussi, spécifiez une chaîne non vide pour le 3e paramètre de LireChaineLocalisee. Ceci permettra d'afficher quand même un texte explicatif et non un mystérieux blanc, même si c'est dans une autre langue. Le texte dans cette valeur par défaut doit être en français, à cause de l'origine de c2iExplorer.

À l'intérieur de l'architecture multilingue

L'architecture multilingue consiste en six fonctions et deux variables globales :

Fonctions

Public Function ValiderFichierLangue(ByVal strFichierLangue As String) As Boolean
Vérifie si le fichier de localisation passé par strFichierLangue existe, que la clé ProgramName de la section @Info de ce fichier correspond au nom du programme et que la valeur de ProgramVer de la section @Info correspond au numéro de la version du programme exécuté actuellement. Cette fonction doit être appelée au démarrage du programme en lui passant le chemin complet du fichier de localisation lu de la base de registres, d'un fichier INI, d'un fichier XML, etc. Retourne une valeur booléenne avec laquelle la variable blnMultilingueActive est affectée. Si la valeur retournée est True, affectez immédiatement à strFichierLangueActuel la valeur du paramètre strFichierLangue.
Public Function LireChaineLocalisee(ByVal strModule As String, ByVal strClef As String, ByVal strValeurDefaut As String) As String
Lit une chaîne du fichier de localisation. ValiderFichierLangue doit être appelé au préalable. strModule est le nom du module. Utilisez idéalement une constante symbolique. strClef est la clé de la chaîne à chercher. strValeurDefaut est la chaîne renvoyée s'il y a une erreur lors de la lecture du fichier de localisation. Placez une chaîne de caractères, la propriété du contrôle ou l'élément du tableau qui contient déjà du texte français. Retourne la chaîne localisée ou, si erreur, strValeurDefaut.
Public Function Existe(ByVal sNom As String) As Boolean
Détermine si un fichier existe. Utilisé par ValiderFichierLangue. sNom contient le chemin complet à vérifier. Retourne une valeur booléenne selon si le fichier existe ou non.
Public Function IsSameString(String1 As String, String2 As String) As Boolean
Effectue une comparaison binaire de deux chaînes de caractères. Utilisé par ValiderFichierLangue. String1 et String2 sont les chaînes à comparer. Retourne une valeur booléenne indiquant si les chaînes sont identiques ou non.
Public Function LireChaineFichierINI(ByVal chnSection As String, ByVal chnClef As String, ByVal chnValeurDefaut As String, ByVal chnFichierIni As String) As String
Lit une chaîne d'un fichier INI. Utilisé par ValiderFichierLangue et LireChaineLocalisee. chnSection est le nom de la section, chnClef est la clé, chnValeurDefaut est la valeur à retourner en cas d'erreur et chnFichierIni est le fichier INI à lire. Retourne la chaîne de caractères lue ou si chnValeurDefaut erreur.
Public Sub StrArray(ByRef strarDest() As String, ParamArray vntarChaines() As Variant)
Initialise un tableau de chaînes de caractères. strarDest contient la référence du tableau à initialiser. Ensuite, passez la liste de chaînes que contiendra le tableau. Cette fonction est un peu plus rapide que Array fourni avec VB. Elle est utile pour charger des chaînes de localisation en boucle. Vous n'avez qu'à spécifier le contenu du tableau à l'indice où vous êtes rendu comme valeur du paramètre strValeurDefaut de la fonction LireChaineLocalisee.

Variables

strFichierLangueActuel
Chemin complet et nom du fichier de localisation actuellement utilisé. Chaîne nulle s'il n'y a pas de fichier valide spécifié.
blnMultilingueActive
Fanion indiquant si un fichier de localisation spécifié dans strFichierLangueActuel est utilisable. Utile pour optimiser le chargement avec des tableaux générés ou des contrôles contenant leur libellé par défaut.

Spécifications du format de fichier de localisation

  • le nom de la section correspond au nom du module (standard, formulaire, classe, etc.)
  • le nom de la clé commence par WProp, Obj ou Code
  • les propriétés d'un module d'interface graphique (tous les types de formulaire, UserDocument) sont précédées de WProp
  • vient ensuite la hiérarchie des objets, propriétés, procédures, etc.
  • chacun des niveaux hiérarchiques est délimité par un point (.)
  • pour une chaîne à localiser se trouvant dans la section (Déclarations), le nom de la clé commence par «Code.Declarations.».
  • le nom de la clé ne contient pas la hiérarchie des objets de l'interface utilisateur. Par exemple, si le contrôle lblCode se trouve dans fraCode, le début de clé sera «Obj.txtCode.» et non «Obj.fraCode.lblCode.»
  • les délimiteurs d'indice sont les parenthèses
  • l'inscription des clés de collection n'est pas obligatoire mais est fortement recommandée
  • pour écrire une clé associée à un indice, utiliser cette syntaxe : indice-->"clef"

Chaînes intentionnellement non traduites

Il y a quelques chaînes qui n'utilisent pas le système de localisation :

frmErreurINI
Ce formulaire s'affiche quand le fichier c2iExplorer.ini n'a pas été trouvé. Comme le nom du fichier de localisation à utiliser se trouve dans ce fichier absent, il est alors impossible de charger les chaînes de caractères localisées. Les chaînes resteront en français tant que les utilisateurs francophones sont les utilisateurs majoritaires de c2iExplorer
MExtraitIcone.GererErrInattendue
Cette procédure affiche un message d'erreur et écrit dans le journal quand une erreur non gérée s'est produite. Étant donné que c'est à peu près le même message dans la boîte de message et dans le fichier journal, il devient fastidieux d'utiliser le système de localisation. Les chaînes resteront en français tant que les utilisateurs et développeurs francophones sont les utilisateurs et développeurs majoritaires de c2iExplorer
UDMsgBox.lblButtons()
Contient les libellés des boutons d'un MsgBox. Elles sont laissées en anglais à cause du manque d'espace et parce qu'elles rappellent le noms des constantes de Visual Basic
