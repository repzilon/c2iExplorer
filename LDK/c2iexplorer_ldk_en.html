How to translate c2iExplorer

c2iExplorer localization architecture has been designed to be simple to use by translators. You have to translate one INI style text file. Use your favourite text editor to translate text between double-quotes ("") except @Info section. Next, edit @Info section like this:

Translator
your first and last name
TranslatorEmail
your email address
QAContact
your translation quality assurance contact first and last name
QAEmail
your quality assurance contact email address
ProgramName
program name. Must stay c2iExplorer
ProgramVer
program version which language pack is made for
XlationVer
translation version. Last number group should be the same as ProgramVer
LastModified
last modification date occurred on file in YYYY/MM/DD format.

Then, translate project report templates in the HTML folder. Do a file copy, then translate then. Do not forget to rename them indicating language between [] as the first characters in file name. Do not translate neither what is between < and > (HTML tag), nor between [ and ] (internally used by c2iExplorer) nor between <!-- and --> (usually a HTML comment, but used in a special manner by c2iExplorer).

Finally, send all your translated files to rener@users.sourceforge.net .

How to support localization in your c2iExplorer modifications

If your modification contains strings to show at the user, you must place them in the localization file. You put the string in the section corresponding to module name. Key name preceding string is object or code hierarchy. If string were a constant if the localization system did not exist, variable prefix is mlg. If your code uses a localizable string to create another one, use str as prefix. After equals sign, put your localizable string between double quotes (""). A space separates neither key from equals sign nor equals sign from string value. In your code, cal  LireChaineLocalisee function passing it module name, key to read and default value if an error occurs.

Important: respect format specifications in the localization file. Also, pass a non-empty string to the 3rd parameter of LireChaineLocalisee. This will allow to show some text instead of a mysterious blank, even if it is in another language. Default text must be in French, because of c2iExplorer origin.

Inside multilingual architecture

Multilingual architecture consists in six functions and two global variables:

Functions

Public Function ValiderFichierLangue(ByVal strFichierLangue As String) As Boolean
Check if localization passed by strFichierLangue exists, that ProgramName key of @Info section of file corresponds to program name and that the ProgramVer value of @Info section corresponds to version number of the running instance of the program. This function must be called on program start passing it localization file full path read form registry base, an INI file, a XML file, etc. Returns a Boolean value with which variable blnMultilingueActive is affected. If the return value is True, affect immediately to strFichierLangueActuel the value of strFichierLangue argument.
Public Function LireChaineLocalisee(ByVal strModule As String, ByVal strClef As String, ByVal strValeurDefaut As String) As String
Read a string from localization file. ValiderFichierLangue must be called first. strModule is module name. Ideally, use a symbolic constant. strClef is key used to get the string. strValeurDefaut is the returned string if there is an error when reading localization file. Put a string, control property or array element already containing text in French. Returns the localized string or, if error, strValeurDefaut.
Public Function FichierExiste(ByVal sNom As String) As Boolean
Check if a file exists. Used by ValiderFichierLangue. sNom contains full path to the file to check. Returns a Boolean value depending on if the file exists or not.
Public Function IsSameString(String1 As String, String2 As String) As Boolean
Does a binary comparison binary of two strings. Used by ValiderFichierLangue. String1 and String2 are the strings to compare. Returns Returns a Boolean value whether if strings are identical or not.
Public Function LireChaineFichierINI(ByVal chnSection As String, ByVal chnClef As String, ByVal chnValeurDefaut As String, ByVal chnFichierIni As String) As String
Read a string from an INI file. Used by ValiderFichierLangue and LireChaineLocalisee. chnSection is section name, chnClef is key name, chnValeurDefaut is the value to return on error and chnFichierIni is the INI file to read. Returns the string read or chnValeurDefaut if error.
Public Sub StrArray(ByRef strarDest() As String, ParamArray vntarChaines() As Variant)
Initialize a string array. strarDest contains reference to the array to initialize. Then, pass the list of strings that the array will contain. This function is a little bit faster than VB built-in Array. It is useful to load localizable strings in a loop. You only have to specify the contents of  the array at the current index as strValeurDefaut argument value of LireChaineLocalisee function.

Variables

strFichierLangueActuel
Full path to localization file currently used. Null string if there is no valid file specified.
blnMultilingueActive
Flag indicating if the localization file specified in strFichierLangueActuel can be used. Useful to optimize loading with generated arrays or des controls containing their default caption.

Localization file format specifications

  • section name corresponds to module name (standard, form, class, etc.)
  • key name begins with WProp, Obj, or Code
  • graphical interface module (any form type, UserDocument) properties are preceded by WProp
  • next objects, properties , procedures, etc. hierarchy comes.
  • each hierarchical level is separated by a period (.)
  • for a string to localize situated in (Declarations) section, key name starts with "Code.Declarations.".
  • key name does not contain user interface object hierarchy. For example, if a control lblCode is inside fraCode, key will begin with "Obj.txtCode." and not "Obj.fraCode.lblCode."
  • index containers are parentheses
  • collection key is not mandatory but highly recommended
  • to write a key associated to an index, use this syntax: index-->"key"

Intentionally un-translated strings

There are some strings that do not use the localization system:

frmErreurINI
This form is shown if file c2iExplorer.ini is not found. Because the localization file name to used in written in this absent file, then it is impossible to load localized strings. strings will stay in French while francophone users form the majority of c2iExplorer users
MExtraitIcone.GererErrInattendue
This procedure shows an error message and writes to the log when an unmanaged error occurred. The message being almost the same in dialog box and in log file, it becomes awkward to use localization system. Strings will remain in French while French speaking users and developers are the biggest part of c2iExplorer users and developers
UDMsgBox.lblButtons()
Contains MsgBox button captions. Left in English because of the lack of space and because they recall le Visual Basic constants names
